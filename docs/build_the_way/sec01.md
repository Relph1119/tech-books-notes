# 第1篇 软件工程师的成长

## 1.1 软件工程的定义

- 软件 = 程序 + 软件工程
- 软件工程是把系统的、有序的、可量化的方法应用到软件的开发、运营和维护上的过程。软件工程包括下列领域：软件需求分析、软件设计、软构建、软件测试和软件维护。
- 工程师的宗旨：我构建、故我在。

## 1.2 单元测试的标准

1. 单元测试应该在最基本的功能/参数上验证程序的正确性。
2. 最好在设计阶段就写好单元测试。
3. 在单元测试之后，机器状态保持不变，就可以不断地运行单元测试。
4. 单元测试应该产生一致、可重复的结果。
5. 保持单元测试的独立性。
6. 单元测试应覆盖所测单元尽可能多的代码路径。
7. 单元测试应集成到自动测试框架中。
8. 单元测试代码必须与产品代码同步保存和维护。

## 1.3 软件工程师的成长

1. 衡量软件工程师的数据指标：项目/任务有多大？花了多少时间和资源？质量如何？是否按时交付？
2. 软件工程包括两方面的工作，一方面是技艺创新，另一方面是坚持不懈的工程工作。
3. 软件工程师的任务清单：
    - 计划：理解工作要求，估计各阶段时间成本，指明依赖关系  
    - 开发：分析需求、生成设计文档、设计复审（和同事审核设计文档）、代码规范（制定或采取合适的规范）、具体设计、具体编码、代码复审、测试（包括自测、改进代码、提交修改）   
    - 记录各阶段用时  
    - 测试报告  
    - 计算工作量  
    - 事后总结  
    - 提出过程改进计划  
4. 从学生到专家的关键转变：专家将更多时间投入到“为什么做”和“做得对不对”（需求分析和测试）上，而非“具体怎么做”（具体编码）上。
5. 扩展自己的舒适区：
    - 离开舒适区
    - 拥抱学习区
    - 寻求高质量反馈
6. 思维误区：
    - 分析麻痹：想弄清楚所有细节、所有依赖关系之后再动手，心理上过于悲观。
    - 给耗牛剪毛：想马上动手修复所有主要和次要的依赖问题，然后就可以完美地达成最初设定的目标，而不是根据现有条件找到一个足够好的方案。
    - 过早优化：容易在某个局部问题上陷进去，花大量时间对其进行优化。
    - 过早扩大化/泛化：只有在遇到同样的需求三次以上，才考虑抽象或泛化，不要一开始就想太多。
7. AI如何重塑全栈工程师的价值：AI帮助工程师重构了“广”和“精”的平衡。
